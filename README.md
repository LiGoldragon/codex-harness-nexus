# codex-harness-nexus

The Codex Harness Nexus on the process library of Process.4, from vision codex-harness-nexus 0:
it hears Codex's hooks, follows each session's rollout, and tells every subscriber what each
session is doing.

- process-library (github LiGoldragon/process-library): the process library, taken by git.
- transport: the place, the sockets and the framing, copied from claude-harness-nexus with the
  Nexus's name made a value (Named).
- codex-harness-process: the processes, Report, Watch, Subscribe, Configure and Discover, built with no_std;
  their types and the enums over them generated by ethos-zero from ethos/ (see ethos/README.md).
- codex-harness-nexus: the program, the manager on its queue and the world it traces into.
- codex-harness-translator: the translator, the CLIs codex-harness, codex-harness-meta and
  codex-harness-subscription, the
  hook client codex-harness-hook and the trace reader codex-harness-trace.

```sh
codex-harness-nexus '{ main /run/user/1000/nexus/main /home/example/.local/state/nexus/main }'
codex-harness-translator '{ main /run/user/1000/nexus/main /home/example/.local/state/nexus/main }'
codex-harness-meta 'Configure.RowCount.256'
codex-harness-meta 'Configure.ThreadDatabase./home/example/.codex/state_5.sqlite'
codex-harness-meta 'Configure.RolloutRoot./home/example/.codex/sessions'
codex-harness-subscription 'Subscribe'
```

With a rollout root configured the Nexus learns a session with no hook. The translator watches
the root and every directory under it, never through a link, and reports each
`rollout-<moment>-<thread id>.jsonl` that appears, the thread id a canonical lowercase UUID, as
Codex writes `<root>/YYYY/MM/DD/rollout-….jsonl`. Each is watched from its first row. A rollout
there before the discovery begins is reported only when a live process holds it open for
writing, as Codex holds each session it runs; a closed one is history and is not read again. A
session named by its SessionStart and discovered is one Watch, with the offset read so far.
